# 0.10.0：通用 JSON 发布分发

本计划按用户批准的 0.10.0 范围实施；不改变 VERSION，不包含提交、推送、发布或用户部署。

## 契约

- 一个编译期 `json-release` Provider；应用配置定义请求矩阵和纯 JSON 查询转换，不按厂商增加 Provider。原有 Codex/Claude 协议保留。
- 引擎独占网络访问；查询不获得文件、进程、环境、模块或 HTTP 能力。请求、输入、查询、输出、制品数量有界；gojq 的 context 取消不等于硬内存隔离。采用可信管理员配置的内嵌 gojq；严格资源隔离跟踪于 [Backlog #18](https://github.com/PMExtra/RedApp/issues/18)，预览不是沙箱。
- 发布身份包含 version/build；渠道单独绑定完整快照。artifact key 跨版本稳定，规范 os/arch/format/scope/variant 区分安装包；必须取得预期 SHA-256，可带 size。checksum sidecar 由引擎取得、解析和匹配。未知平台不推断。
- 元数据、制品与 checksum 的初始 URL 和每次重定向均授权；查询结果不能授予新来源权限。复用现有网络代理和下载完整性机制。
- 元数据独立周期刷新；失败保留旧快照。验证完整快照后原子发布渠道，再按稳定 key 预热。预热失败不撤销有效元数据。
- latest 映射明确默认渠道，stable 不包含预发布；缺少选项明确失败。长效入口只临时重定向到 RedApp 内不可变版本，不能跳到官方。
- 公共 API 提供规范下载选项和本地链接。环境检测仅作推荐，手动选择优先；架构不可靠或 Linux 包型未知时要求选择。
- 实例范围：VS Code、IntelliJ IDEA、PyCharm、CLion。IDE 自身自动更新另按维护原则核实，不声称包代理即接管更新。

## 阶段

1. 请求/查询边界、统一模型、checksum 和来源授权；隔离 fixture 与解析预览，不下载安装包。
2. 配置/持久化、独立刷新、精确预热、渠道下载；先改 OpenAPI 再接 API。若 schema 变化，提升 schema 并为 15→16 实现有界保留数据迁移。
3. 公共下载 UI、首批三个应用预置及 CLion 扩展、中英文文档、综合回归和前端产物。

每阶段验证失败、取消、超限和旧快照保留；最终执行相关完整门禁。不运行 GUI/浏览器。与 stacks 的配置对齐单独列出，不修改另一仓库。

## 接线边界

- 请求矩阵每行向查询提供 `{body, context}`，必须得到一个发布对象；引擎合并时要求 version/build 一致并拒绝重复 key。查询结果是数据，不授予来源权限。
- 发布路径使用 version/build 计算的完整 SHA-256 身份（`r-<digest>`），不从该身份推断版本排序。UI 展示原始 version/build；保留策略必须显式按版本语义处理。
- 渠道发布复用现有 release/resource/channel 表，在一个事务中提交。查询、HTTP、sidecar 和输出验证全部成功后才允许调用该事务；预热在事务成功之后执行。
- JSON Release 的元数据刷新状态与旧快照回退接入 catalog；只对该快照协议启用，现有专用协议维持原行为。
- schema 变化仅服务本功能：applications/application_sources 扩展 Provider CHECK 并新增 json_release_json，后者冻结历史来源授权；新增 release_refresh_status 保存每个来源渠道的尝试、成功时间与失败状态，避免重启后丢失刷新节奏。制品与渠道继续复用既有表。接入 `json-release` 将 schema 从 15 提升为 16；按更正后的 ADR 0001 支持 15→16 备份与事务迁移，其他旧版本只读拒绝。
- stacks 暂无新增必需环境变量。本次内嵌查询不增加 worker、宿主权限或 stacks 配置；不自动修改 stacks。

## 发布前预置覆盖检查

用户已确认 12 项：VS Code，以及 IDEA、PyCharm、CLion、WebStorm、PhpStorm、GoLand、Rider、DataGrip、RubyMine、RustRover、dotUltimate。均复用 JSON Release Provider，新增模板默认禁用，不预热。不包含 MPS/DataSpell/AppCode/Fleet/Aqua/Writerside/Gateway/Toolbox。

预置的官方元数据、平台映射与 checksum sidecar 已核对。dotUltimate 使用 RSU/windowsZIP，仅接受完整 ZIP，拒绝在线安装器和独立 Toolbox 包；ZIP 内 EXE/.dat 整体分发。真实响应回归与引擎验证不能代替安装包下载、实际摘要、归档内容及离线安装验证；这些仍须在发布前完成。保持默认禁用、不预热，不绕过访问限制。
