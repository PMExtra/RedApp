# 0001：1.0 前不做数据迁移

## 背景

项目尚未正式发布或部署。早期版本曾为 schema 编写逐版本迁移，代码与文档中留下大量版本专属规则，维护成本高，而且没有真实存量数据需要保护。

## 决定

- **1.0 之前**：不写数据迁移。任何 schema 变化都提升 schema 版本；启动时遇到版本不同的已有数据目录直接拒绝（只读检查，不改写、不删除），需要换用新的空数据目录。不为每个版本编写单独的升级说明。
- **1.0 起**：每次 schema 变化必须同时提供迁移代码和 golden fixture 测试（用上一版本生成的真实数据目录验证迁移结果）。迁移框架和 schema 基线冻结在阶段 6 完成。

## 后果

- 开发期可以自由调整表结构，不积累迁移代码；现有的迁移遗留代码在阶段 2 清理。
- 1.0 前升级程序意味着放弃旧数据目录，只适用于尚未正式部署的阶段。
- 没有迁移框架就不能发布 1.0。
