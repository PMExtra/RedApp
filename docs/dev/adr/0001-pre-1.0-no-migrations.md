# 0001：1.0 前不做数据迁移

## 背景

项目尚未正式发布或部署。早期版本曾为 schema 编写逐版本迁移，代码与文档中留下大量版本专属规则，维护成本高，而且没有真实存量数据需要保护。

## 决定

- **1.0 之前**：不写数据迁移。任何 schema 变化都提升 schema 版本；启动时遇到版本不同的已有数据目录直接拒绝（只读检查，不改写、不删除），需要换用新的空数据目录。不为每个版本编写单独的升级说明。
- **1.0 起**：每次 schema 变化必须同时提供迁移步骤和 golden fixture 测试（用上一版本生成的真实数据库验证迁移结果）。
- 迁移框架已在 `internal/store/migrate.go` 实现但处于休眠状态：`MinimumMigratableVersion = 0` 表示不支持迁移，任何迁移代码都不会运行。发布 1.0 时把它设为 1.0 的 schema 版本即启用，步骤见 [development.md](../development.md#schema-迁移)。
- 启用后的迁移：只读预检识别版本，拒绝降级和低于最低版本的数据库；先用 `VACUUM INTO` 在数据目录写一份备份；所有步骤、外键检查、与全新 schema 的比对和版本更新在一个事务中完成，失败或崩溃时原数据库不变。

## 后果

- 开发期可以自由调整表结构，不积累迁移代码。
- 1.0 前升级程序意味着放弃旧数据目录，只适用于尚未正式部署的阶段。
- 每个 schema 版本都有提交的 golden fixture（`internal/store/testdata/schema/v<N>.sql`），1.0 后的第一个迁移直接以它为起点。
