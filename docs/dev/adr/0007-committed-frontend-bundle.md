# 0007：提交构建后的前端产物

## 背景

Go 二进制通过 embed 嵌入前端产物。若产物只在构建时生成，`go build`、`go test` 和 `go vet` 都要先有 Node 环境，纯 Go 的开发与 CI 任务会变重。

## 决定

- 前端构建产物提交在 `internal/httpserver/web`。
- 前端源码或依赖有任何变化，都必须重新构建并提交该目录。
- 产物必须可复现：CI 用锁定的 Node 版本和 `package-lock.json` 重新构建，并要求与提交内容逐字节一致。

## 后果

- 只改 Go 的开发者和 CI 任务不需要 Node。
- PR diff 会包含构建产物；评审关注源码，产物一致性由 CI 保证。
- 遇到合并冲突时不要手工编辑产物，应在合并后的源码上重新构建。
