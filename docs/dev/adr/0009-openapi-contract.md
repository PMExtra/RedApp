# 0009：OpenAPI 规范是 HTTP 契约的唯一来源

## 背景

HTTP 路由由 `Server.ServeHTTP` 手写分发，请求和响应形状只存在于 Go 代码和手写的前端类型中。字段风格不一致（PascalCase、重复字段、兼容字段），错误码由 HTTP 状态推导。阶段 3b 重写服务端路由，阶段 4 重写前端，两边需要一份不依赖旧代码的共同契约。1.0 前没有外部客户端，可以做不兼容修改。

## 决定

- `api/openapi.yaml`（OpenAPI 3.1）描述全部 HTTP 路由：公开 API、管理 API、分发路径、页面、静态资源和健康检查。
- 服务端按规范实现，契约测试按规范校验真实响应；前端类型和客户端由规范生成。
- 改接口先改规范，规范与实现在同一个 PR 中修改。设计规则和与旧实现的差异见 [api.md](../api.md)。

## 后果

- 规范之外的路由、字段或错误码视为缺陷。
- 规范的结构检查和契约测试是门禁的一部分（阶段 3b 落地）。
- 1.0 起接口变化需要考虑兼容性，届时另立 ADR。
