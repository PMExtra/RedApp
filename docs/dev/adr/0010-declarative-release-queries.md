# 0010：声明式 JSON 发布查询

## 背景

按 App 新增 Provider 会要求每次增加软件都修改代码。用户批准以一个通用 JSON 发布 Provider 和类似 jq 的纯查询表达式适配不同厂商的更新 API。

## 决定

Provider、请求调度、来源授权、checksum 解析和下载校验仍由编译期代码实现。配置只描述请求和纯 JSON 转换，不允许任意脚本、外部模块、环境变量、文件、进程或查询侧网络访问。这是对 [ADR 0002](0002-compile-time-providers.md) 中“可执行声明”禁令的明确限定：允许无外部能力的数据查询，不允许加载可执行插件或命令。

查询结果必须通过严格的发布模型和 URL 授权校验后才能持久化；预期 SHA-256 不能用下载后自算摘要替代。旧专用 Provider 不强制迁移。

## 资源边界

采用内嵌 gojq，表达式由可信管理员维护；解析预览与定时执行使用同一 runner。限制输入、输出、查询长度、请求数、制品数、并发数与执行 context 时间，不安装环境变量、模块、文件、网络或进程扩展。

gojq 支持 context 取消，但不提供每次查询的硬堆内存配额。输入/输出限额不能限制所有中间结果分配，解析、编译及编码也不是可抢占的硬时间沙箱。错误或高成本表达式仍可能影响整个服务。保存配置或预览成功不证明表达式安全，预览接口不是隔离沙箱；不引入额外可信状态或审批工作流。

严格资源隔离跟踪于 [Backlog #18](https://github.com/PMExtra/RedApp/issues/18)，不阻塞 0.10.0，也不承诺完成时间。后续评估受限进程、硬内存限制、取消与清理、测试接口一致性；本次不新增 worker、不改变宿主权限。
