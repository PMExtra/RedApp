# RedApp 应用级上游设计

状态：Proposed / 待 review，未实施。

完整设计草案 v1    2026年10月27日

## 01 目标与设计边界

本设计让一个 RedApp 实例把另一个 RedApp 实例中的指定应用作为来源，在本地展示、按需缓存并分发。来源属于应用，不属于整个站点；一个实例可以同时使用多个 RedApp 上游、官方原生来源以及本地托管应用。管理员不需要编写 jq，也不需要理解内部网络角色。

### 核心结论

推荐重新设计为 App 加单一 Source，再由一套共享分发运行时处理缓存与下载。不采用 Provider 与 Mirror 长期并存的双重模型。Source 驱动直接提供明确的内容合同：不可变文件、HTTP 路径，或无下载内容。RedApp 本身只是其中一种来源，不是一种整站运行模式。

| 状态 | 本稿中的含义 |
| --- | --- |
| 已确认需求 | 应用级选取；不自动引入新应用；本地分发；无官方回退；逐语言说明覆盖；允许多级；接受破坏兼容和 Provider 重设计。 |
| 推荐决策 | 目标架构、字段划分、wire v1、迁移方法和默认行为建议。尚未逐项批准，不代表已经实现。 |
| 待确认项 | 离线宽限默认值、私有应用再导出默认策略、旧快照保留策略，集中列于第14节。 |

### 实现基线与范围

讨论基线为 RedApp v0.10.1：已有 info、hosted、http-cache、codex、claude-code、json-release 六种 Provider；已有 template_ref 与 overrides、Provider 隔离、UID 与 source_epoch 缓存隔离及旧任务运行时栅栏。RedApp 上游能力尚未实现。本稿允许替换这些内部结构，只保留必要业务行为与用户数据。

现有公开 JSON downloads 加手工 jq 串联存在相对 URL、文件名和陈旧状态处理局限，不作为新产品接口。企业两级缓存是典型部署，但产品不引入 DMZ 或 Internal 角色。

### 非目标

不做整站复制、多主编辑、一个应用多个上游自动切换、官方更新器接管、任意远端脚本执行或自动网络放行。不承诺无限离线可用与即时获知远端撤权同时成立；本稿不包含代码实施或发布时间承诺。

## 02 目标架构与方案取舍

| 候选 | 收益 | 主要代价与结论 |
| --- | --- | --- |
| 保留 Provider 并叠加 Mirror | 短期改动较少 | 类型、配置和调度双轨；复杂度长期累积。不推荐。 |
| 统一 Source 与两类内容合同 | 来源单选；缓存和导出只实现一次 | 需迁移配置与接口，但职责清晰。推荐。 |
| 全部变成统一版本制品库 | 统一文件操作看似简单 | 会伪造 HTTP 版本、清单或摘要，info 也被强行制品化。不推荐。 |

### 最小概念与职责

- App 是本地展示实体：稳定 UID、本地路径、说明覆盖、可见性和运营策略。App 内只保存一个当前 Source；纯本地说明页可以没有内容来源。

- Source 是来源配置的判别联合，kind 建议为 hosted、http、codex、claude-code、json-release、redapp。驱动按来源类型复用，不为每个应用编写驱动；JSON 配置仍是通用能力。

- Connection 保存可复用 RedApp 地址、信任绑定和只读凭证引用。远端选取是连接上的操作，不再建立独立 Discovery 插件框架。

- 共享分发运行时统一处理本地鉴权、解析结果、下载、Range、缓存提交、预热和错误状态。来源驱动只负责发现或解析内容以及读取字节，不拥有另一套缓存。

### 单向依赖

```text
管理与同步 → App / Connection → Source 解析 → Snapshot
本地请求   → 本地访问检查 → 共享分发运行时 → Source 读取
RedApp 导出 → 同一份 Snapshot 与共享分发运行时
```

RedApp 驱动只消费远端合同，不能保存旧 provider_key 后在本地重新执行官方发现。远端支持什么内容、如何校验和安装，由版本化合同声明；不另造 remoteProvider 类型轴。原生驱动与 RedApp 驱动共用相同本地分发入口。

### 删除而不是永久包裹

迁移完成后删除旧 Provider 调度入口，避免新增 Mirror 专属业务层、双份缓存或远端 jq 配置拼接。安装器与签名校验保留少数明确的受信实现，不建立任意插件执行框架。旧配置只保留在迁移备份或回滚包中，不进入新运行时的 inactive 分支。

## 03 产品体验与管理流程

### 一个实例中的三种来源

| 本地应用 | 当前来源 | 用户看到的行为 |
| --- | --- | --- |
| Codex | RedApp 连接 研发分发站 | 说明可本地改；安装与文件地址均为当前实例。 |
| Claude Code | RedApp 连接 软件分发站 | 从另一上游取签名原文和文件；本地兼容安装器完成校验。 |
| 企业工具 | 官方 JSON release 来源 | 直接使用原生来源能力，与前两项并存。 |

同一个实例还可以创建本地 hosted 文件应用或 info 说明页，不改变以上应用来源。网络拓扑不进入应用类型命名。

### 添加连接并选取应用

1. 添加连接：输入名称、HTTPS 地址；公共目录允许匿名，受限目录选择只读凭证。测试协议、证书、实例身份及支持能力，错误必须可解释。

2. 浏览目录：只列当前身份有权发现且允许导出的应用，默认公开目录只含 public 应用。展示名称、来源实例、内容能力和最近更新时间。

3. 勾选子集：预览本地名称、路径、语言说明和默认策略。远端以后新增应用不会自动引入；后续必须再次选取。

4. 处理冲突：同路径或疑似重复绑定只提示冲突，不能覆盖或自动接管既有应用。管理员改路径、跳过，或明确进入现有应用切源流程。

5. 确认创建：保存远端稳定 UID 和初始快照，默认不下载全部文件；可选预热当前选定版本。远端纯说明应用也可以引入，redapp Source 返回无内容快照。

### 应用详情与说明编辑

详情显示“来源”“上次成功同步”“当前快照”“缓存状态”和明确的异常原因。zh-CN 与 en 分别显示“跟随上游”或“本地覆盖”；编辑并保存只覆盖当前语言，另一语言不变。上游更新不覆盖本地文字；“恢复跟随上游”删除该语言 override，立即使用最近有效上游文本。

切源、禁用连接和删除被引用连接先显示受影响应用、缓存与进行中任务。失败时不悄悄改成官方来源。用户侧只出现本地页面和本地下载入口，不要求用户访问上游。

## 04 数据模型与字段归属

下表为推荐目标模型，不要求独立数据库表一一对应。声明配置、远端观测快照和运行状态分离；前端不能把完整远端对象作为可编辑配置提交。

| 对象或字段 | 权威归属 | 写入规则 |
| --- | --- | --- |
| App uid 与 route | 本地 | UID 永久稳定；路径重命名不改变 UID。路径冲突必须预览。 |
| App source | 本地选择 | 一个当前来源；redapp 含 connection_id 与 remote_app_uid。 |
| Connection | 本地管理 | origin、expected_instance_uid、credential_ref；秘密单独存储。 |
| RemoteSnapshot | 选定上游 | 保存远端 UID、revision、展示、内容与合同版本；只读替换。 |
| description_overrides | 本地 | zh-CN/en 独立可选字段；缺失表示继承，空字符串表示显式留空。 |
| 名称 图标 摘要 | 推荐跟随快照 | 本稿只确认说明可覆盖；其他展示覆盖不默认扩张。 |
| enabled access | 本地并受授权上界约束 | 本地可以收紧，不能扩大上游私有内容的使用或再导出权限。 |
| pinning taxonomy | 本地 推荐 | 置顶或版本固定、分类标签独立；固定只能引用真实可用内容。 |
| prewarm retention cache | 本地 推荐 | 本地预热、回收、容量与 stale 策略；不能改来源事实。 |
| 版本 文件身份 摘要 签名 | 来源内容合同 | 不可通过说明编辑或配置导入随意覆盖；完整性证据有类型。 |
| 缓存与授权状态 | 本地运行态 | 完整度、观测时间、错误、访问 generation；不混入用户配置。 |

### 身份与状态的最小关系

本地 App UID 不依赖远端名称。远端绑定使用 instance UID 加 app UID；重命名继续跟随，删除后同名新建必须是新 UID，不能接管旧绑定。连接地址发生变化但实例身份一致时仍须重新验证；身份不符则暂停并要求明确重绑。

content_epoch 隔离来源内容空间；security_generation 使凭证、授权或连接安全变更后的旧任务失效。两者不得混成“所有变更都删缓存”。旧 source_epoch 可在迁移中映射为内容代次，具体存储字段名属于实现提案。

## 05 展示继承与来源切换规则

### 逐语言说明的唯一优先级

```text
effective_description[locale] =
  local_override[locale] 存在 ? local_override[locale]
                               : snapshot.description[locale]
```

没有该语言上游文本时采用明确的页面语言回退规则，但不写入 override。保存空字符串是本地刻意留空；reset 删除字段，而不是把当前上游内容复制到本地。快照更新以远端 revision 为单位原子替换，页面不得混用两代受校验内容。

### 预置与模板不再成为隐藏的第三层

推荐把预置定义为“新建时的一次性初值”：填写来源配置和本地展示初值，不作为持续的远端默认层。原生来源的展示默认可以来自该来源快照或已保存本地值；RedApp 来源只用远端快照加显式本地覆盖。不存在预置、旧模板、上游和本地四方递归合并。

迁移旧 template_ref 与 overrides 时先按旧版本规则求出当前有效展示，再转换为新模型可见值或显式覆盖，并生成差异报告。不能把旧模板中的值误认为远端继承值；需要保留继承的语义必须明确转换，而不是猜测。

### 何时改变内容代次

| 变化 | content_epoch | 安全访问 generation |
| --- | --- | --- |
| 来源驱动或内容命名空间改变 | 增加 | 增加并终止旧解析提交 |
| 改绑远端实例或 app UID | 增加 | 增加 |
| 同来源发布新版本或目录 revision | 不增加；更新 snapshot | 按授权状态决定 |
| 凭证轮换但身份和内容绑定未变 | 不增加；不必丢相同内容缓存 | 增加，旧任务须重新授权 |
| 本地说明 分类 预热策略变化 | 不增加 | 仅访问控制变化需要更新 |
| 连接 origin 改变 | 验证为同实例才可保留；否则增加 | 必须增加并重新验证 |

任务捕获 App UID、content_epoch、连接安全 generation 和快照 revision。写回、缓存提交和发出新响应前校验当前值；旧任务不能污染新来源。已有字节只有在身份、摘要与当前授权均可证明一致时才可复用。

### 切源必须显式

新架构允许更换来源驱动，不再受旧 Provider 不能原地更换限制。先预检目标内容能力、安装兼容性、固定版本映射和路径冲突，再一次性切换；保本地 UID 与策略，说明覆盖默认保留并提示差异。失败可恢复旧配置，但恢复也是新的代次，不能复活旧任务。

## 06 统一来源合同与六类业务行为

驱动最小职责是读取快照、解析内容引用和打开字节流。内部方法名可为 readSnapshot、resolveContent、openContent；它们是提案，不是现有接口。共享运行时掌握访问检查、缓存、并发、重试和本地响应。能力按内容合同声明，不按旧 Provider 名称猜测。

| 原业务 | 目标来源与内容形态 | 必须保留的行为 |
| --- | --- | --- |
| info | 无 Source；或 redapp 返回 none | 只有展示，无版本和下载；仍可被选取和再导出。 |
| hosted | hosted → artifacts / directory | 本地文件目录 revision；稳定文件身份、一致分页、上传替换产生新对象。 |
| http-cache | http → paths | 按规范化路径解析；可变响应及 HTTP validator；不要求枚举清单。 |
| codex | codex → artifacts / releases | 原生发布发现与平台选择；经共同运行时下载。 |
| claude-code | claude-code → artifacts / releases | 官方签名 manifest 原字节、受信校验及兼容本地安装器。 |
| json-release | json-release → artifacts / releases | 通用 JSON 配置和映射；明确摘要来源及缺失值，不等同官方签名。 |
| RedApp 上游 | redapp → 远端声明的任一形态 | 只读远端合同和字节，不执行原生发现；支持以上全部业务。 |

### 三种快照结构而不是任意 map

- releases：发布列表、渠道指针、平台和不可变文件引用。版本名称是展示标识，不单独承担内容身份。

- directory：托管目录 revision 和文件条目；目录变更不伪造软件版本。全部分页必须属于同一 revision。

- paths：仅声明路径访问合同与可选已知路径，不捏造完整清单、版本或上游摘要。none 则只有展示与权限信息。

Source 驱动可实现它确实支持的能力。所有来源都必须经过导出能力检查，但不要求所有来源都能枚举或做“预热全部”。path 模式只预热明确输入或已知路径；info 无预热。

### 拒绝不兼容而不是降级

wire、内容合同、签名或 installer recipe 语义版本不兼容时，绑定或同步明确失败。不得退回公开 JSON 拼接、跳过校验、猜测 Provider，或回退官方。安全相关能力必须显式识别；未知可选展示字段才允许忽略。

## 07 RedApp 只读协议提案

以下端点与字段均为未实现的 wire v1 提案；版本名只属于本协议草案，不代表已确定数据库或配置交换版本。协议保持少量只读资源，由同一访问检查和分发服务支撑。

| 接口提案 | 职责 |
| --- | --- |
| GET /api/upstream/v1/instance | 返回稳定 instance_uid、协议版本和能力；验证连接身份。 |
| GET /api/upstream/v1/apps | 发现当前授权且可导出的应用；分页，不暴露秘密。 |
| GET /api/upstream/v1/apps/{uid}/snapshot | 返回展示、权限上界、内容形态和 revision；支持 ETag。 |
| GET /api/upstream/v1/apps/{uid}/entries | 按 revision 和 cursor 读取发布或目录条目；paths 可不支持。 |
| GET /api/upstream/v1/apps/{uid}/artifacts/{id} | 只返回选定不可变对象字节；支持 HEAD 和合同允许的 Range。 |
| GET /api/upstream/v1/apps/{uid}/paths/{path} | 仅 paths 模式；规范化路径后访问该应用的来源。 |

### 快照示例

```json
{
  "wire_version": 1,
  "instance_uid": "inst_A", "app_uid": "app_7",
  "revision": "rev_42",
  "display": {"name": "Example Tool",
    "description": {"zh-CN": "说明", "en": "Description"}},
  "content": {"mode": "artifacts", "catalogue": "releases",
    "contract": "release-artifacts/1"},
  "installation": {"recipe": "local-tool/1"},
  "export": {"visibility": "public", "redistribution": "allowed"}
}
```

示例名称仅说明合同结构，recipe 列表和字段名仍需实现评审。description 包含当前导出实例的有效展示，因此 A 的说明被 B 本地覆盖后，C 默认继承 B 的有效说明；内容身份和签名不会因展示变化而被改写。

### 分页与错误语义

cursor 必须绑定 app UID、revision、查询条件及授权范围。不能跨 revision 拼页；旧 revision 已不可取时返回明确 REVISION_GONE，重新拉取完整快照。建议统一错误码：UNAUTHORIZED、FORBIDDEN、APP_GONE、ARTIFACT_GONE、REVISION_GONE、INCOMPATIBLE、LOOP_DETECTED；HTTP 状态保留标准含义。

## 08 内容身份与签名验证

### 不可变文件与可变路径分开存储

不可变 artifact ID 指向特定字节对象，而不是“latest”或文件名。发布和目录条目引用该 ID；内容替换必须产生新 ID 或明确的新内容代次。下载绑定快照 revision 与对象身份，不能在旧 URL 下静默返回新文件。不能证明对象稳定的 JSON 或 HTTP 来源，必须先完整获取并固化为本地对象，或明确使用 paths 合同；不能仅凭版本名和 URL 声称不可变。

```json
{
  "artifact_id": "obj_8", "filename": "tool.tar.gz",
  "size": 123456,
  "digest": {"algorithm": "sha256", "value": "&lt;hex&gt;",
             "evidence": "upstream-reported"},
  "signature_ref": "manifest_obj_2",
  "download_path": "artifacts/obj_8"
}
```

以上为未实现示例。size 未知时为 null；摘要缺失时明确缺失，不能造零值。下载路径必须相对当前应用导出根，不能是任意外部 URL。传输后可计算本地摘要用于去重和完整性检查，但不得把它标成上游摘要或官方签名。

| 证据或状态 | 能证明什么 | 不能证明什么 |
| --- | --- | --- |
| complete | 传输完成并满足适用校验 | 不单独证明来源真实性 |
| local digest | 本地字节一致和损坏检测 | 不是上游承诺或官方证明 |
| upstream reported digest | 与可信上游声明一致 | 普通 JSON 摘要不是官方签名 |
| official signature verified | 符合指定官方验证规则 | 不授权远端执行任意脚本 |

### Claude manifest 与安装器

保留并传输官方签名 manifest 的原始字节，不在其中重写 URL、路径或 JSON 排版。另行建立本地 artifact 映射；受信本地 installer recipe 校验 manifest，并把被签名文件身份映射到本地下载入口。不能改变受签名约束的 hash、名称或平台标识。

recipe 是本地实现的有限兼容集合，带语义版本；远端只能声明受支持 recipe 标识，不能附带任意代码。若官方安装协议无法安全映射到本地入口，应阻止该安装方式并显示兼容错误，而不是去掉签名检查。

### HTTP 路径的真实边界

路径缓存键包含本地 App UID、内容代次、规范化路径和响应变体；按 ETag、Last-Modified 等有效 validator 处理可变内容。无 validator 时不能把两次响应拼成同一对象，跨断点续传必须重新下载或采用可证明安全的方法。

## 09 下载同步与预热流程

### 普通下载

1. 用户访问本地应用入口；执行本地 enabled、access 以及已知的上游授权检查。安装脚本和文件链接仍指向当前实例。

2. 根据当前 Source 与 snapshot 解析精确对象或路径，并捕获内容代次与安全 generation；固定版本不被渠道更新悄悄改写。

3. 完整缓存且当前策略允许时本地返回；否则只向该 Source 读取。redapp Source 只能请求所选连接的该应用，不请求官方或另一连接。

4. 下载写临时对象，达到适用长度和摘要或签名校验要求后原子提交。被截断、取消或验证失败的对象永远不标 complete。

5. 响应开始与缓存提交前检查 fence。新来源或新安全 generation 下，旧任务不得继续作为有效新请求或提交结果。

对于要求整文件校验才能信任的内容，推荐校验通过后再提供“已验证下载”；受信安装器即使流式传输，也必须完成校验后才安装。不能把尚未校验的流量标为已验证缓存。

### 渠道与快照更新

后台同步只刷新已绑定应用。完整验证新快照后原子替换渠道指针与条目引用；新增远端应用不会创建本地应用。旧的不可变对象可按 retention 保留，但 latest 解析只使用当前有效快照。展示变化不清空文件缓存；受校验事实变化必须重新验证。

### 预热与回收

预热与普通下载走同一授权、解析和缓存路径，不建立特权旁路。支持当前版本、已固定版本或选定目录文件；path 模式只接受明确路径集。并发去重、大小预算与取消均由共享运行时负责。

retention 决定保留哪些本地对象，cache 决定容量与回收；两者都不保证上游仍可重新取得旧文件。回收引用计数需要考虑正在下载、当前快照和固定项，不能删掉被活动任务使用的对象。

### HTTP 响应要求

统一实现或明确协商 200、206、304、416、HEAD、Content-Range 与未知 Content-Length。不能把 206 局部对象标成完整文件；304 必须有对应已验证本地表示。Range 不支持时显式使用完整下载或返回标准错误，不伪造范围响应。

## 10 故障离线与撤权语义

可用性与授权分开：暂时联系不到上游不等于被撤权；已明确撤权也不能伪装成网络故障而继续新分发。推荐使用少量可解释状态，不引入复杂的短租约体系。

| 观测结果 | 本地新请求行为 | 缓存与恢复 |
| --- | --- | --- |
| 在线并获授权 | 按当前快照正常服务 | 同步和按需填充 |
| 超时 DNS TLS 或上游 5xx | 完整缓存可按本地 stale 策略使用；未缓存内容失败 | 保留观测时间与错误；恢复后验证再更新 |
| 明确 401 或 403 | 停止受影响范围的新分发，不官方回退 | 隔离保留字节，修复凭证并重新授权后才恢复 |
| 确认 app 删除或不再导出 | 停止该应用新分发，显示来源已失效 | 保留本地说明与管理记录；不接管同名新 UID |
| 单个文件 404 或 revision 淘汰 | 只使该对象或快照失效；重新解析 | 不能据此断言整个应用被删除 |
| 合同或签名不兼容 | 阻止相应内容服务，明确原因 | 不降校验、不改用公共接口 |
| 本地禁用 app 或连接 | 停止新分发与新任务 | 不自动直连官方；管理员明确恢复 |

### 离线可用性的前提

只有已完整缓存且具备所需元数据和适用校验结果的内容才可能离线服务；半缓存、仅目录索引或缺失签名原文不算离线可用。stale 策略应按公开与私有内容设定可配置窗口；具体默认值列为待确认，不引入统一短租约要求。

界面区分“上游暂不可达，正在使用缓存”和“已知撤权或删除，已停止分发”。超过本地允许窗口后停止新 serve。离线期间无法得知新的远端撤权；这是明确的时效边界，不能宣传为即时撤权。

### 删除与正在进行的下载

推荐收到明确撤权、删除或本地禁用后，拒绝所有后续新响应，并尽力取消尚未结束的传输和缓存提交；已交付字节无法收回。不得用长期无状态下载链接绕过当前访问检查。应用删除不立刻销毁可审计数据，实际清理遵循本地 retention 和管理员确认。

网络失败按有界退避重试；权限错误不无限重试。重新上线时先核对实例和应用 UID、权限与合同，再恢复任务，不仅凭“HTTP 又返回 200”解除隔离。

## 11 安全与多级分发

### 连接与请求边界

- 默认 HTTPS 并验证证书；支持企业受信 CA，但不以跳过验证替代配置。固定 scheme、host、port 和 API 基路径，实例 UID 是身份绑定而非 TLS 的替代。上游展示文本按不可信输入清洗，不允许脚本或任意远程嵌入。

- 凭证最小只读，仅用于指定上游；日志、配置导出、前端和 snapshot 不包含秘密。公共上游可匿名，私有目录必须明确授权。

- 重定向默认只允许已验证的同 origin 范围；禁止把 Authorization 发送到其他 origin，禁止跳到官方或 CDN 绕过本地层级。跨源迁移走连接编辑与重验证。

- 相对路径规范化一次并拒绝路径穿越、编码绕过、绝对 URL、双斜杠主机和非法查询。请求目标始终由连接与应用合同组成，不让远端文本决定任意出站地址。

- 对私网连接使用管理员明确批准的网络目标范围；阻止云元数据等危险目标，处理 DNS 重绑定。限制连接与读取超时、重定向、并发、响应体、解压、清单大小和分页次数。

### 导出权限不是站点运行模式

每个应用单独决定能否导出及允许的受众，连接目录只展示该身份可选的子集。public 目录默认只发现 public 应用；private 内容需要明确导出授权。能下载 private 应用不自动意味着能再导出。

推荐 wire 声明再分发上界：禁止、向授权下游、允许公开。B 的本地 access 只能收紧 A 的上界，不能把 A 的私有应用无意设为 public；B 向 C 导出时继续施加该限制。具体默认授权选择待确认，不能因允许多级而默认放开私有传播。

### 适度防环与实例生命周期

连接时拒绝绑定自身实例。同步和下载传递有界的实例链路信息，各跳追加自身 UID，发现重复即拒绝；同时用内部 hop 上限和超时限制兜底，不给普通用户增加拓扑配置流程。链路字段不能作为授权凭据，也不能完全信任上游自报的 hop 数。

备份恢复同一逻辑实例可保留 UID；克隆为并行新实例应生成新 instance UID。应用复制也产生新 app UID。远端身份变更、同名重建或不一致恢复都不能自动接管，需管理员明确重绑。

### 多级保证的范围

A 到 B 到 C 每跳只访问自己的选定上游；B 和 C 的官方请求数应为零。多级不意味着端到端加密或不可转发 DRM；对不受信下游无法技术上收回已经交付的明文文件，权限模型须如实描述这一边界。

## 12 破坏兼容范围与安全迁移

用户允许全部 breaking changes，因此目标不是长期兼容旧结构，而是一次性转换后只运行一套系统。破坏兼容不意味着可丢数据；配置、托管文件、有效展示、权限与回滚能力必须可验证。

| 旧内容 | 目标处理 | 淘汰或保护措施 |
| --- | --- | --- |
| 六种 Provider 配置 | 转换为 App.source 或无内容 App | 只保留来源配置真实需要的字段；不运行旧 Provider 分支 |
| template_ref 与 overrides | 求值后转换为新展示与显式覆盖 | 报告继承变化；不保留多层递归合并 |
| UID 与 source_epoch | 保留 App UID并映射内容代次 | 旧任务全部失效；不能因同路径合并身份 |
| 旧缓存 | 校验身份与摘要后可复用 | 无法证明关联的缓存隔离或重新拉取；不能猜测 |
| hosted 原始文件 | 保留字节并生成目录 revision | 校验数量、大小、摘要及引用；不得静默删文件 |
| 配置交换 v2 与 schema 17 | 发布新格式并提供一次性导入器 | 新版本号待定；不能假定兼容旧读写端 |

### 迁移执行顺序

- 先只读 dry run：列出每个应用的字段转换、展示差异、权限差异、路径冲突、无法映射项和预计缓存处理。未解决冲突不应用。

- 建立带校验和的数据库、配置、秘密引用及 hosted 文件备份；冻结变更或使用一致快照。迁移操作应幂等并有明确状态记录。

- 在事务或可恢复阶段中转换配置，重建索引并校验应用数、UID、访问权限、语言说明和文件清单；通过后一次切换运行入口。

- 回滚恢复同一时间点的数据和对应旧程序，不能让旧程序读新格式；冻结窗口之后的新写入需要单独恢复方案，不能声称任意回滚无损。

### 切换 删除与导入

来源切换可以跨驱动，但必须走第5节预检；旧源配置仅进入明确回滚备份，不作为运行时 inactive 配置。删除被引用连接时默认拒绝直接删除，必须先逐项改绑、禁用或删除引用应用；不能自动转原生来源。

跨实例导入不携带运行中任务、有效凭证或隐式信任绑定；连接重新确认，私有导出重新授权，同路径冲突必须预览。配置导出不得包含秘密和短期下载凭证。

### 必要运维信息

按应用记录当前来源、内容代次、安全 generation、同步结果、拒绝原因、命中率、未完整缓存和上游字节量。审计记录切源、改权限、连接重绑及 reset；日志脱敏。管理员应能定位问题，无需读取内部实现堆栈。

## 13 测试矩阵与验收标准

用小型确定性 fixture 覆盖原有六类业务，并在 A 到 B 到 C 两跳中运行同一组合同测试。A 可访问模拟原生源；B 和 C 的官方域名访问被计数并禁止，断言请求数为零。

| 测试域 | 关键用例 | 通过标准 |
| --- | --- | --- |
| 六类来源 | info、hosted、HTTP、Codex、Claude、JSON | 每类都可选取、展示和按实际能力分发；不伪造枚举能力 |
| 多源混合 | 两个 RedApp 连接加原生来源及本地应用 | 互不串源；只引入勾选子集；新增远端应用不自动出现 |
| 展示覆盖 | zh-CN/en 分别编辑、空值、reset、上游更新 | 逐语言规则一致；内容身份与本地策略不被覆盖 |
| 身份与替换 | 改名、删后同名、实例克隆、目录删除替换 | 按稳定 UID；不接管同名；新字节不会冒充旧对象 |
| 快照与分页 | hosted 多页中途更新、cursor 过期 | 同 revision 一致；不跨代拼装；明确失败和重试 |
| 完整与半缓存 | 完整、部分、截断、取消、磁盘满、重启 | 只有完整且校验通过才可作为有效缓存；可恢复而不串源 |
| HTTP 语义 | 200/206/304/416、HEAD、未知长度 | 范围与条件请求正确；不把局部响应当完整文件 |
| 完整性与安装 | 摘要错误、签名篡改、manifest 原文、recipe 不兼容 | 失败闭合；原文未改；安装器只使用本地入口 |
| 离线与授权 | 失联、401/403、删除、revision 淘汰、重新上线 | stale 与撤权不同；已知撤权后不新 serve；不官方回退 |
| 并发与栅栏 | 下载中切源、凭证轮换、连接重绑、旧任务提交 | 旧结果不能污染新来源；相同合法缓存不过度失效 |
| 安全边界 | SSRF、路径穿越、跨源跳转、循环、过大响应 | 阻断危险目标和凭证泄漏；资源限制生效 |
| 迁移与导入 | v2/schema17 转换、同路径、失败恢复、回滚 | 数据清点一致；无静默覆盖；旧运行路径可最终删除 |

### 必须额外验证的反例

私有上游导入后把本地设成 public 应被阻止；只有 manifest 没有文件不能宣称离线可用；文件 404 不能删除整个应用；未知合同不能绕过校验；凭证轮换后的旧任务不能提交，但已验证同一内容也不应无故被清空。

通用能力的验收门槛是全部六类业务通过，不以 release 类单一路径跑通作为“所有 Provider 已支持”。测试可用 CLI 和服务级 fixture 完成，不依赖 GUI 自动化。

## 14 实施顺序与待确认决策

### 推荐阶段与退出条件

| 阶段 | 交付内容 | 退出条件 |
| --- | --- | --- |
| 一 固定合同 | App/Source 模型、内容形态、wire 与权限错误语义 | 六类业务均可表示；不靠旧 Provider 名称补语义 |
| 二 建立单一运行时 | 共享下载缓存、fence、来源驱动和迁移 dry run | 原生六类行为不退化；旧新运行态不混用 |
| 三 实现 RedApp 来源 | 连接、子集选取、导出、逐语言覆盖及多级分发 | A到B到C全矩阵通过；无官方回退 |
| 四 切换与淘汰 | 备份迁移、运维状态、一次性兼容导入和删除旧路径 | 迁移可验证可恢复；不保留永久双轨系统 |

阶段顺序是建议，不是排期承诺。每阶段都以自动化证据和迁移演练退出；不可为了先发布“通用上游”而把 hosted、HTTP 或 info 留为隐含例外。

### 少数需要最终拍板的默认值

| 决策 | 本稿建议 | 尚未确定 |
| --- | --- | --- |
| 离线 stale 策略 | 公开与私有分开配置；已知撤权后停止新分发 | 默认宽限、最大窗口和是否允许私有离线 |
| 私有内容再导出 | 默认不因可下载而可再导出；逐应用明确授权 | 是否默认禁止，或采用受限的授权下游模式 |
| revision 与缓存保留 | 保留当前引用与必要固定对象；旧 revision 有明确淘汰信号 | 上游历史 revision 保留期限和本地默认容量 |
| 迁移发布策略 | 一次性转换、可预览、备份回滚；最终删除旧路径 | 新配置交换与数据库版本号及旧格式支持窗口 |

### 已明确不再作为约束的旧设计

不要求保留现有 Provider API 或 provider_key，不要求来源类型永远不能切换，不保存长期 inactive 原生分支，不把 Mirror 叠成第二套来源实现。上述变化来自允许破坏兼容、从全局寻找最优解的最新要求；业务需求与数据保护要求仍然有效。
