# 镜像其他 RedApp 实例

[English](mirrors.md)

一个 RedApp 实例可以把另一个 RedApp 实例上的指定应用作为来源。典型的部署分两级：DMZ 中的实例访问官方来源，内网实例只能访问 DMZ 实例。客户端只访问内网实例，页面、安装器和下载地址都是它自己的。

镜像按应用进行：由你选择要镜像哪些应用，上游以后新增的应用不会自动加入。镜像只访问它的上游，从不访问官方来源。可以有多级（A → B → C），一个实例也可以同时镜像多个上游的应用，并继续提供自己的应用。

## 添加上游

在管理后台打开 **上游**，添加另一个实例的地址，例如 `https://dmz.example`。地址格式为 `http(s)://主机[:端口]`，不带路径：RedApp 从主机的根路径提供服务。

保存前 RedApp 会读取对方实例的身份。上游必须运行支持镜像的 RedApp 版本。实例不能把自己作为上游。访问上游 API 时使用全局代理；下载文件时与其他应用一样，使用被镜像应用的代理。

## 镜像应用

打开一个上游，浏览它发布的应用，选择要镜像的应用，并确认本地的厂商 ID 和应用 ID（默认与上游相同）。本地不存在的厂商会按上游的厂商信息创建。

| 上游应用 | 本地应用 |
| --- | --- |
| 应用信息 | 应用信息 |
| 托管文件 | 沿用上游目录列表设置的 HTTP 缓存 |
| HTTP 缓存 | HTTP 缓存 |
| Codex、Claude Code | 相同的 Provider，使用 RedApp 自己的安装器 |
| JSON 发布 | 读取上游下载选项的 JSON 发布 |

要让本地已有的应用改为来自上游，例如内置的 Codex 应用，请填写相同的本地 ID，并确认接管已有应用。它必须使用相同的 Provider。接管后保留本地设置（代理、分类、Tag、缓存规则、版本保留、预热），展示和来源从此跟随上游，并开始新的 source epoch。

## 跟随上游的内容

- **展示**：名称、说明、图标、使用说明、目录列表设置，以及 JSON 发布的默认和隐藏安装包，跟随上游。每一项都可以在应用设置中按语言覆盖；重置后重新跟随上游。使用说明保留模板变量，因此 `{{base_url}}`、`{{app_url}}` 显示的是本实例的地址。
- **来源**：上游应用的地址。不能在应用中修改；请修改上游的地址，这会让从它镜像的每个应用开始新的 source epoch。
- **本地设置**：其余设置（代理、分类、Tag、缓存规则、版本保留、预热）都属于本地，从不跟随上游。

JSON 发布的镜像每 300 秒为每个渠道读取一次上游的下载选项，所有安装包都从上游下载，并按上游提供的 SHA-256 摘要校验。由于发布设置属于上游，它没有自己的预热选择。

## 检查与状态

RedApp 每 15 分钟检查一次全部镜像应用（首次检查在启动 15 分钟后），在应用设置中点击 **立即检查** 可以立即检查单个应用。

| 状态 | 含义 |
| --- | --- |
| 最新 | 最近一次检查成功。 |
| 错误 | 最近一次检查失败（例如 `UPSTREAM_UNAVAILABLE`）。应用保留最后的值，继续提供服务。 |
| 不再发布 | 上游不再发布该应用。应用保留最后的值，设置中显示其模板缺失。 |

当上游地址已指向另一个实例、上游应用更换了 Provider，或上游发来本实例不接受的值时，检查会停止更新该应用并报告 `UPSTREAM_INCOMPATIBLE`。实例迁移后，请重新保存上游以重新验证。

## 多级与环路

镜像的应用本身也可以被镜像。每个实例都会传递其应用来源经过的实例链；当链中包含本实例时，RedApp 拒绝镜像（`LOOP_DETECTED`），镜像时和每次检查时都会核对。应用发给自身的请求（它的来源绕回了它自己）以 `508 LOOP_DETECTED` 拒绝。

新鲜期不会在多级之间累加：HTTP 缓存文件带有剩余的新鲜时间，因此下游缓存保留文件的时间不会超过上游。

## 故障

上游不可达时，已在本地缓存的文件照常提供，发布渠道保留最后的有效状态；尚未缓存的文件会失败。上游不再发布的应用不会在本地被自动禁用，请自行决定保留、禁用还是删除。

## 停止镜像

在应用设置中点击 **停止镜像**，应用会变成普通应用，保留当前的值，包括来源地址。有内置模板的应用会重新链接到该模板，当前的值作为覆盖保留。只有没有任何应用从某个上游镜像时，才能删除该上游。

导出的配置把镜像应用写成当前值的独立副本，不包含上游和镜像绑定。镜像应用只能复制为独立副本，导入也不能覆盖它。
