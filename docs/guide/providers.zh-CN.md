# Provider

[English](providers.md)

RedApp 中每个应用都有一个 **Provider**。Provider 决定应用提供什么内容，以及如何获取和缓存文件。Provider 在创建应用时选择，之后不能更改。

## 概览

| Provider | ID | 上游基础 URL | 提供内容 | 缓存与清理 |
| --- | --- | --- | --- | --- |
| 应用信息 | `info` | 无 | 详情页和使用说明 | 无文件 |
| 托管文件 | `hosted` | 无 | 管理员上传或导入的文件 | 保留到管理员删除 |
| HTTP 缓存 | `http-cache` | 必填；1–16 个来源 | 来源 URL 下的任意文件 | 路径规则，默认 TTL 300 秒，手动和自动清理 |
| Codex | `codex` | `https://releases.openai.com/codex`（可修改） | 经过校验的 Codex 发布和安装器 | 渠道 TTL 60 秒，版本清理，可选保留和预热 |
| Claude Code | `claude-code` | `https://downloads.claude.ai/claude-code-releases`（可修改） | 经过校验的 Claude Code 发布和安装器 | 渠道 TTL 60 秒，版本清理，可选保留和预热 |

所有 Provider 共用[部署配置](configuration.zh-CN.md#字段参考)中的下载限额。

## 厂商与应用

- 应用隶属于厂商。应用的公开地址为 `/<vendor>/<app>`。
- ID 由小写字母、数字和单个连字符组成，最长 63 个字符。厂商 ID `all`、`admin`、`api`、`assets` 和 `health` 为保留名称。
- ID、所属厂商和 Provider 在创建后固定。
- 名称和描述分英文和简体中文两种语言，两种语言的名称都必填。
- 只有应用及其厂商都启用时，应用才会公开。
- 应用可以有多个分类和私有 Tag。Tag 用于后台和公开搜索，但从不公开显示。

### 删除

- 内置应用不能删除，可以禁用。
- 删除自定义应用是永久操作。它会移除该应用的缓存、托管文件和历史，并中断其正在进行的下载和任务。其他应用不受影响。
- 如果应用的工作未在 15 秒内停止，删除会保持待完成状态。可以重试，或重启 RedApp 以完成删除。
- 只有没有应用的厂商才能删除。

### 更换来源

修改上游来源 URL（对 HTTP 缓存而言，还包括来源列表、顺序或策略）会开始一个新的 **source epoch**：

- 新请求只使用新来源。从旧来源缓存的文件不会用于新来源。
- 旧缓存保留在磁盘上。可以在缓存页面选择旧来源来查看和清理。
- 指标历史在同一应用下继续累计。

## HTTP 缓存

HTTP 缓存镜像一个或多个上游 HTTP(S) 来源中的文件。

### 路径映射

对 `/<vendor>/<app>/<path>` 的请求会获取 `<来源 URL>/<path>`。

| 来源 URL | 请求 | 上游 URL |
| --- | --- | --- |
| `https://files.example.internal/tools` | `/example/files/builds/tool.zip` | `https://files.example.internal/tools/builds/tool.zip` |

- 拒绝查询字符串、路径穿越、编码的斜杠和控制字符。
- 客户端不能指定上游主机。
- 不转发客户端的 Cookie 和 `Authorization` 头。
- 文件以下载（`attachment`）方式返回，从不作为网页返回。

### 请求处理

| 请求 | 行为 |
| --- | --- |
| `GET`，未缓存 | 一边下载并存储，一边把文件流式返回给客户端 |
| `GET`，已缓存且新鲜 | 直接从磁盘返回，不访问来源 |
| `GET`，已缓存但过期 | 向来源重新验证（`ETag`、`Last-Modified`）；`304` 保留副本，`200` 替换副本 |
| `HEAD`，未缓存 | 向来源发送 `HEAD`，不存储任何内容 |
| 单段字节范围 | 基于缓存文件返回 `206`。文件仍在下载时，如果来源声明了文件长度，所需字节一到即返回该范围；否则返回完整文件 |
| 多段字节范围 | 忽略范围，返回完整文件 |
| 条件请求 | 支持 `If-None-Match`、`If-Modified-Since`、`If-Match` 和 `If-Unmodified-Since` |

多个客户端请求同一个未缓存文件时，共享同一次上游下载，并且各自在字节到达时就收到数据。文件完整到达后才会被存储；下载失败或不再有客户端读取时，缓存中不留下任何内容。文件仍在下载时，响应只带来源的 `ETag`；已存储且来源没有 `ETag` 的文件使用 `"sha256-<hex>"`。

客户端请求中的缓存指令（`Cache-Control: no-store`、`no-cache`、`max-age`、`Pragma`）会被忽略：它们不会强制回源，新鲜度只由规则和上游响应头决定。`only-if-cached` 仍然生效，未命中时返回 `504`。

如果来源把文件标记为不可缓存，并发的每个客户端各自直接传输，受 writer 上限约束（耗尽时返回 `503 TRANSFER_CAPACITY`）。只有在请求期间缓存副本持续变化时才返回 `503 CACHE_CONTENDED`。

### 新鲜度

TTL 决定缓存文件保持新鲜的时长。它**不是**保留期：过期文件会留在磁盘上，直到被清理。

RedApp 按以下顺序确定 TTL：

1. **匹配的缓存规则。** 第一条模式匹配路径的规则决定 TTL，忽略上游的 `Cache-Control`、`Age` 和 `Expires`。
2. **上游 `Cache-Control`。** 没有匹配规则时，使用 `s-maxage`，否则使用 `max-age`，并扣除 `Age` 或 `Date` 反映的已过时间。如果存在 `Cache-Control` 但没有有效寿命，TTL 为 0。
3. **应用默认 TTL。** 仅在响应完全没有 `Cache-Control` 时使用，默认 300 秒。

从不使用 `Expires`。来源的 `no-cache`、`must-revalidate` 等指令不会缩短计算出的寿命。

**TTL 0** 表示每次请求都先向来源重新验证。文件仍会被存储，因此来源故障时可以作为回退。

### 路径规则

规则匹配解码后、以 `/` 开头的应用相对路径。对于 `/example/files/releases/tool.zip`，路径为 `/releases/tool.zip`。

| 模式 | 类型 | 匹配 |
| --- | --- | --- |
| `/` | glob | 所有文件 |
| `/releases` | glob | 文件 `/releases` 以及目录 `/releases/` 下的所有内容 |
| `/releases/` | glob | 仅目录 `/releases/` 下的文件 |
| `/**/*.zip` | glob | 任意深度的 `.zip` 文件 |
| `/releases/[^/]+\.zip` | re2 | 直接位于 `/releases/` 中的 `.zip` 文件；必须匹配整个路径 |

- **glob** 使用 doublestar 语法（`*`、`**`、`?`、`[...]`、`{a,b}`）。匹配某个目录的模式也匹配该目录下的所有文件。
- **re2** 是 Go RE2 正则表达式，必须匹配整个路径。不支持反向引用和环视。
- 规则按顺序检查，**第一条匹配的规则生效**。调整顺序会改变结果。
- 在缓存设置中使用 **测试匹配** 检查模式与路径是否匹配。

导出配置中保存的策略示例：

```yaml
http_policy:
  stale_fallback: true
  rules:
    - match: {type: glob, pattern: /releases/}
      ttl_seconds: 3600
    - match: {type: re2, pattern: '/channels/[^/]+\.json'}
      ttl_seconds: 0
  auto_cleanup:
    - match: {type: glob, pattern: /releases/}
      basis: last_access
      age_seconds: 2592000
```

### 不共享的响应

有些上游响应不能提供给其他客户端。RedApp 把它们直接传给发起请求的客户端，不存储：

- `Cache-Control: no-store` 或 `private`，除非有显式规则匹配该路径
- 带 `Set-Cookie` 的响应
- `Vary` 包含 `Accept-Encoding` 以外内容的响应

匹配的缓存规则会有意覆盖 `no-store` 和 `private`，使文件被缓存并在公开下载地址共享。`Set-Cookie` 和 `Vary` 的边界仍然有效，规则不能覆盖。

当 TTL 大于 0 的规则覆盖上游 `no-store` 或 `private` 时，RedApp 为每次上游获取记录一条警告事件。

### 旧缓存回退

`stale_fallback` 默认开启。

- 所有来源都在响应之前因网络错误、超时或 `5xx` 状态失败时，RedApp 返回已过期的缓存副本而不是错误。来源已经响应后才中断的下载不能回退，见[多个来源](#多个来源)。
- 只使用同一应用、同一 source epoch 的完整副本，没有最大过期时长。
- 每次回退记录一条警告事件。
- `404` 和 `410` 不属于故障，会直接返回给客户端。
- 关闭 `stale_fallback` 时返回错误。

### 多个来源

HTTP 缓存应用可以列出 1 到 16 个来源 URL。

| 策略 | 行为 |
| --- | --- |
| `ordered`（默认） | 按列出的顺序尝试 |
| `round_robin` | 每次从下一个来源开始，再尝试其余来源 |
| `random` | 按随机顺序尝试，每个来源最多一次 |

- 只有来源在响应之前失败（网络错误、超时或 `5xx` 状态）时，才会切换到下一个来源。
- 下载没有总时长限制。60 秒内没有收到数据时，传输中断。
- 一个文件始终取自单个来源。来源响应后，如果响应带有强验证器（非弱 `ETag`，或比其 `Date` 至少早 1 秒的 `Last-Modified`），并且来源用同一文件中恰好缺少的字节应答，中断的传输会用字节范围向同一来源续传（总共最多 6 次尝试）。否则下载失败：正在接收的客户端看到传输中断，且不存储任何内容。不会拼接不同来源的部分下载。
- 验证器（`ETag`、`Last-Modified`）只对签发它的来源复用。
- 没有健康检查或权重。新鲜缓存命中不会推进 `round_robin`。

### 刷新

在缓存页面可以强制重新验证：

- **刷新单个文件**：重新验证一个已缓存路径，即使它仍然新鲜。
- **按模式刷新**：为匹配的已缓存文件生成预览。执行后在后台重新验证全部文件。
- 刷新只适用于已启用且所属厂商也已启用的应用的当前来源。新响应不允许缓存或期间被修改的文件会标记为已跳过。

刷新只处理已在缓存中的文件，不会发现新的上游文件；发现新文件请使用预热。

### 手动清理

手动清理移除匹配模式且早于截止时间的缓存文件。

1. 选择模式、时间基准和截止时间。
   - `fetched_at` 是文件正文最后一次下载的时间。
   - `last_access` 是客户端最后一次使用文件的时间，按分钟记录。从未被访问的文件使用 `fetched_at`。
2. 检查预览，其中列出将要移除的确切文件。
3. 执行。RedApp 只移除预览中的文件，并跳过预览之后被使用过的文件。

正在下载的文件会在下载结束后移除。

### 自动清理

保存至少一条规则之前，自动清理处于关闭状态。

- 每条规则包含模式、时间基准（`fetched_at` 或 `last_access`）和最小年龄。
- 由**第一条**模式匹配文件的规则决定。即使该文件尚未达到年龄，也不会继续尝试后面的规则。
- RedApp 每 15 分钟运行一次自动清理，首次运行在启动 15 分钟后。
- 每轮每个应用最多扫描 1,000 个文件、移除 100 个。下一轮从上次停止处继续。
- 只处理已启用应用的当前 source epoch。旧 epoch 需要手动清理。

### 预览与回执

| 项目 | 值 |
| --- | --- |
| 预览有效期 | 10 分钟 |
| 同时生成的预览数 | 8 |
| 每页条目数 | 默认 25，最多 100 |
| 执行后回执保留 | 24 小时 |

重启会中断正在运行的刷新或清理，且不会恢复；请重新生成预览。

### 限制

| 设置 | 范围 |
| --- | --- |
| 应用默认 TTL | 0–86,400 秒（默认 300） |
| 规则 TTL | 0–86,400 秒 |
| 缓存规则 | 最多 32 条 |
| 自动清理规则 | 最多 32 条 |
| 模式长度 | 1–1,024 字节 |
| 清理最小年龄 | 60–315,360,000 秒 |
| 来源 | 1–16 个 |

## Codex 与 Claude Code

这两个 Provider 分发官方发布。RedApp 从上游获取元数据和二进制，校验、缓存后连同修改过的安装器一起提供。校验内容见[安全](security.zh-CN.md#上游校验)。

### 渠道

| Provider | 渠道 |
| --- | --- |
| Codex | `latest` |
| Claude Code | `latest`、`stable` |

渠道指向某个版本。RedApp 按**渠道 TTL** 缓存渠道结果：默认 60 秒，允许 1–86,400 秒。已发布的版本不会变化，因此其文件一直缓存到被清理。

### 安装器

每个应用在 `/<vendor>/<app>/` 下提供 `install.sh` 和 `install.ps1`。应用页面显示使用你的公共地址的命令。安装器从 RedApp 下载，而不是从上游下载。

### 版本清理

在缓存页面选择最低版本。预览列出低于该版本的已缓存版本，执行后移除它们。版本元数据和指标历史会保留。

- RedApp 无法比较的版本会在预览中列出并保留。
- 执行只移除预览中的文件。正在下载或读取的文件在传输结束后移除。
- 预览 10 分钟后过期。如果期间来源发生变化，不会移除任何文件；请重新预览。
- 较早的 source epoch 也可以用同样的方式清理。

### 版本保留

版本保留只保留最新的已缓存版本，默认关闭。

- 把 **保留最新** 设为 N（1–1,000，默认 3）。
- RedApp 只统计当前来源中至少有一个完整缓存文件的版本。
- 除最新 N 个外，RedApp 始终保留渠道当前指向的版本、正在下载或读取的版本，以及无法比较的版本。
- 如果某个渠道无法验证，整轮跳过。
- 保留任务每 15 分钟运行一次，每轮每个应用最多移除 100 个版本。也可以手动预览并执行。
- 手动预览使用已保存的设置，请先保存修改。预览 10 分钟后过期；执行后结果保留 24 小时。
- 不处理旧的 source epoch 和已禁用的应用。已禁用的应用（或其厂商已禁用）不能手动预览或执行，请先启用两者。

### 预热

预热在客户端请求之前下载文件。

| 平台列表 | 值 |
| --- | --- |
| Codex（6） | `darwin-arm64`、`darwin-x64`、`linux-arm64`、`linux-x64`、`win32-arm64`、`win32-x64` |
| Claude Code（8） | `darwin-arm64`、`darwin-x64`、`linux-arm64`、`linux-x64`、`linux-arm64-musl`、`linux-x64-musl`、`win32-arm64`、`win32-x64` |

- **自动预热**（仅发布类应用）：选择渠道和平台。RedApp 每 15 分钟下载这些渠道指向的版本。已预热的版本会跳过；失败在下一轮重试。
- **手动预热**（发布类和 HTTP 缓存应用）：启动一次性任务。HTTP 缓存可以提供文件路径、UTF-8 路径清单，或由 RedApp 遍历其目录列表的目录路径。支持 HTML、nginx `autoindex` JSON 和 Caddy `browse` JSON 格式的目录列表。

| 预热任务限制 | 默认值 | 最大值 |
| --- | --- | --- |
| 文件数 | 10,000 | 100,000 |
| 目录深度 | 16 | 32 |
| 读取字节数 | 10 GiB | 1 TiB |
| 时长 | 1 小时 | 24 小时 |

- 整个服务同时只运行一个预热任务。没有队列；运行期间再次启动会被拒绝。
- 已禁用的应用（或其厂商已禁用）不能预热，缓存页面会提示先启用。预热设置仍可编辑。
- 每个目录列表最大 2 MiB。
- 取消任务不会取消公共客户端也在等待的下载。
- 重启会把运行中的任务标记为已中断，不会恢复。
- 已结束的任务保留 24 小时。
- 预热不计入指标和排行中的公开下载。实际从上游获取的字节会计入。

## 托管文件

托管应用提供管理员给出的文件。

- 从浏览器**上传**文件，或从 `http`、`https` URL 一次性**导入**。
- 每个文件在应用内有一个路径，例如 `tools/setup.exe`，并通过 `/<vendor>/<app>/tools/setup.exe` 提供。
- 每个文件的大小上限为 `max_artifact_bytes`（默认 4 GiB）。
- 文件保留到管理员删除。修改文件请对其使用 **替换**；期间发生的冲突修改会被拒绝。
- 上传和导入在进行中可以查看进度，也可以取消。
- 导入 URL 可以带查询字符串，例如签名下载链接。RedApp 只使用一次，不保存也不显示。带凭据或片段（`#...`）的 URL 会被拒绝。
- 已删除的托管应用的文件仍可下载和删除，但不能添加或替换。
- 下载支持字节范围和条件请求。

## 应用信息与使用说明

**应用信息** 应用只有详情页和使用说明，不提供文件。其他 Provider 也都有使用说明。

使用说明按语言用 Markdown 编写，允许原始 HTML、JavaScript 和外部资源。它们显示在沙箱框架中，见[安全](security.zh-CN.md#使用说明沙箱)。

内置 Codex 和 Claude Code 应用带有来自预置模板的默认说明。保存空说明会保持为空，不会恢复默认值。使用 **重置** 可以恢复模板文本。

### 模板变量

变量在页面显示时替换，值经过 HTML 转义。未知变量保持原样。

| 变量 | 值 | 示例 |
| --- | --- | --- |
| `{{base_url}}` | 有效公共地址，不带结尾 `/` | `https://downloads.example.internal` |
| `{{public_origin}}` | 与 `{{base_url}}` 相同 | `https://downloads.example.internal` |
| `{{app_path}}` | 应用路径 | `/openai/codex` |
| `{{app_key}}` | 应用键 | `openai/codex` |
| `{{app_url}}` | 应用完整地址 | `https://downloads.example.internal/openai/codex` |
| `{{app_name}}` | 页面语言下的应用名称 | `Codex` |
| `{{latest_version}}` | 当前来源中已知的最新版本，没有时为 `<version>` | `0.50.0` |

Markdown 示例：

```sh
curl -fsSL '{{base_url}}{{app_path}}/install.sh' | sh
```
