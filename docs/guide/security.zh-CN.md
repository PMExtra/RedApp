# 安全

[English](security.md)

本文说明 RedApp 保护什么、信任什么，以及哪些仍由你负责。

## 信任模型

| 参与方 | 信任程度 |
| --- | --- |
| 管理员 | 完全信任。可以修改所有设置，包括带 JavaScript 的使用说明。 |
| 匿名用户 | 可以浏览公开目录并下载已发布文件，不能修改任何内容。 |
| 反向代理 | 仅在列入 `trusted_proxies` 时受信任。 |
| 上游来源 | 发布元数据和二进制会被校验。HTTP 缓存内容按上游交付原样转发。 |
| 导入的配置 | 在管理员检查预览并确认之前不受信任。 |

RedApp 只有一个管理员账号，没有角色或按用户划分的权限。

## 管理员认证

### 密码

- 首次启动时，RedApp 生成随机密码并在日志中打印一次。请保护该日志，并在登录后修改密码。
- 新密码长度必须为 12 到 72 字节。修改密码需要提供当前密码。
- 密码以 bcrypt 哈希存储。
- 修改密码会使所有会话退出登录，包括你自己的会话。
- 没有找回丢失密码的命令。

### 会话

| 属性 | 值 |
| --- | --- |
| 有效期 | 自登录起 8 小时，不随操作延长 |
| 存储 | 服务器内存；重启后所有人退出登录 |
| 并发会话 | 最多 128 个 |
| Cookie | `redapp_session`，`HttpOnly`、`SameSite=Strict`、`Path=/admin` |
| `Secure` 标志 | 请求 origin 为 HTTPS 时设置 |

请求 origin 来自 TLS 或可信代理转发的 scheme。位于 HTTPS 反向代理之后时，请配置 `trusted_proxies`，使 Cookie 带有 `Secure`。

### 请求保护

- 除登录外，每个管理 API 请求都需要有效会话。
- 每个修改数据的管理请求都需要 `X-CSRF-Token` 头，后台会自动发送。
- `Origin` 头与请求 origin 不一致的管理 API 请求会被拒绝。

### 登录频率限制

- 每个客户端 IP 每 5 分钟最多尝试登录 10 次，成功的尝试也计入。
- 5 分钟窗口结束后限制重置。
- 密码错误和触发限制返回相同的响应，攻击者无法区分。
- 设置了 `trusted_proxies` 时，客户端 IP 取自可信代理头；否则为直连对端地址。

## 匿名访问

无需登录，任何能访问 RedApp 的人都可以：

- 打开**已启用**厂商和应用的首页、目录、厂商页面和应用页面。
- 阅读使用说明。
- 下载已启用应用的安装器、发布文件、托管文件和 HTTP 缓存文件。
- 调用健康检查端点。

匿名用户永远看不到私有备注、Tag、代理设置、上游凭据或已禁用的应用。RedApp 不限制谁可以下载。如有需要，请通过反向代理或网络限制访问。

## 使用说明沙箱

管理员使用 Markdown、HTML 和 JavaScript 编写使用说明，并可以加载外部资源。这些说明显示在沙箱框架中：

- 框架没有同源权限（opaque origin）。
- 脚本和外部资源可以运行。
- 脚本无法读取管理员会话，无法访问父页面，也无法携带访问者的凭据调用 RedApp API。
- 框架通过 `postMessage` 向父页面报告高度，不交换其他数据。

说明仍会在访问者的浏览器中运行任意代码。只发布你信任的脚本和外部资源。

## 导入的配置

配置包可能来自其他管理员或其他组织。

- 导入预览以源码文本显示说明的变化，从不渲染或运行。
- 如果包修改了使用说明，必须先明确确认信任这些说明，导入才会执行。
- 配置包不能包含发布分发规则、签名密钥或信任设置，含有这些内容的包会被拒绝。
- 导入的厂商和应用初始为禁用状态。
- 只有导出的管理员勾选时，才会导出代理凭据和私有备注。

## 上传

### 图标

| 规则 | 值 |
| --- | --- |
| 格式 | PNG、JPEG、静态 SVG |
| 上传大小 | 2 MiB |
| 栅格尺寸 | 每边最多 4096 像素，总计最多 4,194,304 像素 |

- PNG 和 JPEG 图片会被解码并重新编码，从而去除元数据。
- SVG 文件按允许列表检查形状、渐变和表现属性。脚本、事件处理器、外部引用、外部命名空间元素和实体会导致拒绝，而不是被删除后接受。
- 图标以严格的内容安全策略返回。

### 托管文件

- 上传大小上限为 `max_artifact_bytes`（默认 4 GiB）。
- URL 导入接受不含凭据的 `http` 和 `https` URL。最多跟随 4 次重定向，且从不从 HTTPS 降级到 HTTP。重定向时丢弃凭据和 Cookie。
- 托管文件和 HTTP 缓存文件以附件方式返回，带 `X-Content-Type-Options: nosniff` 和沙箱内容安全策略，浏览器不会把它们当作网页运行。

## 上游校验

| Provider | 校验 |
| --- | --- |
| Claude Code | 发布清单使用固定的 Anthropic OpenPGP 密钥签名（RSA 4096、SHA-512）；每个二进制按已签名清单中的 SHA-256 校验 |
| Codex | 每个发布文件按发布元数据中的 SHA-256 摘要校验 |
| HTTP 缓存 | 没有发布者签名。本地 SHA-256 只用于检测存储损坏。 |

所有上游流量的共同规则：

- 始终校验 TLS 证书，没有跳过校验的选项。
- 下载的文件在完整大小和校验和通过后才会发布。续传的下载会重新校验。
- 上游响应不得使用内容编码，因此校验和对应实际提供的字节。
- 发布类 Provider 只在配置的来源内跟随重定向，从不把 HTTPS 降级为 HTTP。
- HTTP 缓存可以跟随重定向到其他 HTTPS 主机。主机变化时丢弃凭据和 Cookie。
- 客户端不能选择上游主机，只能请求配置来源之下的路径。

选择镜像作为来源不会让任意文件变得可信。来自镜像的 Codex 和 Claude Code 文件仍须通过同样的校验。

## 出口代理凭据

- 代理 URL 可以包含用户名和密码。
- API 从不返回已存储的密码。后台显示脱敏值，保存时不修改密码会保留已存储的密码。
- 公开页面、日志和事件从不包含代理凭据。
- 凭据存储在数据库中。请保护数据目录及其备份。

## 反向代理信任

- 只相信 `trusted_proxies` 中对端发送的转发头。
- 可信对端发送的畸形转发头会以 `400` 拒绝。
- RedApp 只检查 `Host` 的语法。请在代理处限制允许的域名。
- 公共地址设置只影响生成的链接，不授予也不限制访问。

配置示例见[运维](operations.zh-CN.md#反向代理)。

## 安装器完整性

RedApp 提供官方 Codex 和 Claude Code 安装器，仅做最小修改：

- 原始安装器连同其许可原样保存在仓库中。
- 补丁保持最小：把下载重定向到你的 RedApp 服务，并保留上游的校验步骤。
- 每次安装器更新都必须精确应用补丁并通过离线检查后才会被接受。
- 安装器从 RedApp 下载。Codex 和 Claude Code 运行时仍会访问各自的服务。

Claude Code 安装器还会安装一个禁用客户端自动更新的启动器，使更新经由 RedApp 获取。
