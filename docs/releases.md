# 版本说明

## v0.7.14

移除空状态栏预留高度及厂商名称强制两行高度，数量紧接名称，保留 60px 厂商水印。禁用应用保留灰度、背景和管理入口；滚动末项、隐藏闲置滚动条、悬停箭头、键盘和触摸操作保持。不包含预览调参界面或演示数据，不涉及 schema 或 0.8.0。

验证覆盖不同数量、宽窄容器、中英文、标题行数、Add 对齐及边界滚动；执行 Go vet/race、Shell 安装器回归、前端类型/DOM、生产构建及真实 HTTP/数据/说明文档/Docker CLI。发布要求精确 main 提交通过原生 Windows PowerShell 7/5.1 和 Linux 双架构 CI，再按不可变摘要验证双架构发布镜像。CLI/DOM 验证不替代真实浏览器像素或触控验收。

本地 Go vet/race、Shell 安装器回归、前端类型检查及 130 项 DOM 测试、生产构建、真实 HTTP/数据/说明文档 CLI 和隔离 Docker 运行通过。发布要求精确 main 提交通过原生 Windows 及双架构 CI，再按不可变摘要验证双架构镜像。CLI/DOM 验证不能代替真实浏览器像素或触控验收。

厂商 Logo 统一去掉背景与边框；公开详情恢复 48px 高，管理卡片按头部高度展示半透明比例 Logo，保留标题和数量链接空间。应用图标规范不变，卡片预览场景单独增至 44px。应用条缩小间距及内边距，固定两行标题、降低行高，移除 tile 可见禁用文字但保留灰色和可访问状态；添加项显示 Add App / 添加应用。修正 tile 继承 flex-wrap 与末项 100% 链接高度导致的横向溢出风险，末项正常参与布局。箭头仅鼠标悬停时可见且隐藏时不可点击/聚焦，键盘方向键/Home/End 可滚动；触控沿用原生滚动。滚动条颜色仅滚动期间显示，预留固定高度；边界渐变随实际 scrollWidth/clientWidth/scrollLeft 更新。

本地已通过 Go vet/race、Shell 安装器回归、前端类型检查及 128 项 DOM 测试、生产构建、真实 HTTP/数据/说明文档 CLI 与隔离 Docker 运行。CLI/DOM 验证不等同于真实浏览器像素或触控验收；发布前须核对精确提交的原生 Windows 及双架构 CI，并另行获得发布授权。本版不修改 schema 9、安装器或 0.8.0 规划。

后台支持动态厂商和应用、双语资料、静态图标与启用管理。GeneralHttp、Codex、ClaudeCode 为三个并列 Provider；BaseUrl 可配置，换源使用独立 source epoch，旧缓存保留供显式管理，应用累计指标维持稳定身份。Codex/ClaudeCode 的安装器原文、patch、信任材料及已有发布验证保持不变。

GeneralHttp 提供多源顺序、轮询或随机回源，路径 TTL 规则、故障旧副本回退开关、手动刷新和默认关闭的自动清理。TTL 0 每次回源，仍可保留完整副本供失败回退；实际覆盖与回退按共享回源操作记录警告。跨源重试完整重取，不拼接未经全局摘要证明相同的半截内容。清理和刷新共用服务端分页冻结预览，分批执行整个选中集合，并复查 revision、source epoch、generation 和最近访问。清理后的新请求不会通过旧共享回源任务取得已退役副本，已有读者可正常完成。

回归覆盖千级资源的分页与跨轮推进、执行中配置变更、刷新/回退分类、容量边界、旧目录保护、前端 DOM 与非 UTC 时间，以及安装器治理。发布仍须通过精确 main 提交的原生 Linux amd64/arm64 和 Windows PowerShell 7/5.1 CI，再按不可变 digest 验证双架构镜像。没有 GUI、真实官方 CLI、原生 Windows ARM64 或 macOS 验收；没有 S3 后端、旧数据迁移或用户部署操作。

## v0.6.3

单制品大小上限支持容量字符串，环境变量、CLI、YAML 和显式 JSON 使用统一的 `go-humanize v1.1.0` 解析规则，兼容原有整数字节值。GB 使用十进制、GiB 使用二进制，推荐 `4GiB`；默认仍为 4294967296 字节，范围仍为 1 字节至 1 TiB。此设置不限制整个应用或缓存总体积。配置优先级、数据格式和默认 8080 端口保持不变。

彻底删除入站 Host 白名单配置、环境变量和 CLI。接受语法合法的 Host，保留可信代理链、安全 origin 推导、会话认证、Origin/CSRF 和 Cookie 保护；PUBLIC_URL 只控制生成链接。域名与网络访问策略由反向代理负责，healthcheck 使用本地监听地址。

writer 统一更名为 `download_limits.max_writers` / `REDAPP_MAX_WRITERS` / `--max-writers`，reader 继续使用 `max_readers` / `REDAPP_MAX_READERS` / `--max-readers`。这是 1.0 前的破坏性配置调整，没有旧别名；删除的文件字段和 CLI 会报错，旧环境变量不再读取。升级配置时删除 Host 白名单并更名 writer，参考[当前配置表](operations.md#启动配置)。

## v0.6.2

恢复无需配置文件的默认启动：原生 `redapp` / `redapp serve` 和默认容器均可直接使用内建值及部署环境变量。无需预先创建或挂载 `/etc/redapp/config.json`。

默认自动读取 `/etc/redapp/config.yaml`，不存在时继续启动。手动路径优先级为 `--config` > `REDAPP_CONFIG`，一旦选中就不再读取默认文件；显式 `.json` 仍兼容。手动文件缺失、选中文件非法或不可读均报错。部署字段优先级为 CLI > env > 所选文件 > 默认值，列表整体替换；具体字段与迁移示例见[运维说明](operations.md#启动配置)。已有 JSON 部署请通过 `REDAPP_CONFIG` 或 `--config` 继续指定原文件，不自动发现 `config.json`。

默认 Host 仅允许监听端口上的 localhost/回环地址，无默认可信反代；远程域名/IP 需明确设置允许列表，PUBLIC_URL 不扩大入站授权。后台 PUBLIC_URL > 环境 > 安全请求 origin、后台业务设置、旧目录只读保护和数据格式保持不变。显式配置验证不会创建数据目录。YAML 解析使用固定 `go.yaml.in/yaml/v3 v3.0.5`，沿用同一严格字段/值校验，拒绝重复键、类型错误和多文档/别名等歧义。

回归重点为单文件选择、实际无参数/环境变量启动、YAML 重启持久性、JSON 兼容、Host/代理边界、非法配置失败保护及无配置容器健康检查。发布要求精确 main 提交完整 CI 与双架构发布后 digest 运行验证；不执行 GUI 或用户部署操作。

## v0.6.0

**破坏性多应用架构升级：必须使用全新空数据目录。** 不导入旧版配置、缓存或历史；检测到旧版或未知目录会拒绝启动，旧目录保持不变。部署改为显式 JSON 配置，旧逐字段 CLI、部分环境变量和旧公共/隐式 Codex API 路径不再兼容。先保留旧实例的完整备份，再按[升级说明](multi-application-v0.6.0.md)创建新实例；不能将新数据库交给旧程序读取。
